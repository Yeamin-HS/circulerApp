# API contract v1 (Story 1.5)

Frozen on 2026-11-17 (ADR-010). The machine-readable contract is `docs/openapi.json`; this
page is the human summary. Run the backend and open `/docs` for the interactive version.

- Schemas: `backend/app/core/schemas.py`
- Routes: `backend/app/api/` (stubs that return 501 until their story builds them)
- Frontend types: `frontend/src/types/api.d.ts`, generated by `npm run types`
- Guard: `backend/tests/test_contract.py`

## 1. Conventions

- JSON in and out, UTF-8. File uploads are `multipart/form-data` with one field, `file`.
- Auth: `Authorization: Bearer <JWT>`. Tokens last 60 minutes; there is no refresh token in
  v1 (ADR-001). Where the frontend keeps the token is decided in Story 2.1.
- Ids are integers. Dates are `YYYY-MM-DD`; timestamps are ISO 8601 in UTC.
- Unknown fields in a request body are rejected (422).
- A user only ever sees their own data. Another user's resource returns 404, not 403.
- `null` in a fact-card field means "not stated in the circular".

| `GET /me` | seeker | — | 200 `UserOut` | 401 | 2.1 |

| `POST /me/cv` | seeker | file: PDF or DOCX, ≤ 5 MB | 200 `CVDraft` | 401, 403 `consent_required`, 413, 415, 422, 429 | 2.3 |

| `POST /circulars` | seeker | file: PDF, JPG or PNG, ≤ 10 MB, ≤ 20 pages | 201 `CircularDetail` | 401, 413, 415, 422, 429 | 3.1 |
| `GET /circulars` | seeker | — | 200 list of `CircularSummary` | 401 | 3.1 |
| `GET /circulars/{circular_id}` | seeker | — | 200 `CircularDetail` | 401, 404 | 3.2 |
| `GET /circulars/{circular_id}/eligibility` | seeker | — | 200 `EligibilityReport` | 401, 404, 409 `profile_required` | 3.3 |
| `POST /circulars/{circular_id}/ask` | seeker | `AskRequest` | 200 event stream (§5) | 401, 404, 422, 429 | 4.2 |
| `GET /chunks/{chunk_id}` | seeker | — | 200 `ChunkOut` | 401, 404 | 3.2 |
| `GET /health` | — | — | 200 `Health` | — | done |

Not part of the frozen contract (v1.1): `POST /admin/eval`, `GET /admin/metrics`.

Notes:
- `POST /me/cv` stores nothing. The draft becomes a profile only through `PUT /me/profile`,
  which also deletes the uploaded file (SOP hard rule 6).
- `GET /circulars` is sorted by deadline, earliest first, circulars with no deadline last.
  `verdicts` is null until the user has a confirmed profile.
- `ask` works without a profile for `fact_lookup` and `summary` questions. An eligibility
  question without a confirmed profile ends with a `final` event whose answer asks the user
  to confirm their profile.

## 3. Main schemas

| `CVDraft` | `profile`, `warnings[]` (for example hidden text found in the file) |
| `ProfileOut` | `profile`, `confirmed_at`, `version` |
| `FactCard` | `organisation`, `posts[]`, `deadline`, `age_limit`, `age_as_of`, `fee`, `apply_mode`, `how_to_apply`, `apply_link` |
| `PostReq` | `title`, `vacancies`, `grade`, `min_degree`, `subjects`, `min_result`, `experience_years`, `age_limit` |
| `CircularSummary` | `id`, `title`, `organisation`, `source_type`, `deadline`, `created_at`, `verdicts` |
| `CircularDetail` | `id`, `title`, `source_type`, `pages`, `created_at`, `fact_card`, `posts[]` (`id` + `requirements`) |
| `ChunkOut` | `id`, `circular_id`, `post_id`, `page`, `kind`, `text` |
| `EligibilityReport` | `circular_id`, `profile_version`, `posts[]` |
| `PostEligibility` | `post_id`, `title`, `verdict`, `checks[]`, `gaps[]` |
| `Check` | `name`, `status`, `required`, `actual`, `evidence[]` |
| `AskRequest` | `question` (1–500 characters) |

Every `FactCard` and `PostReq` field is a value with its evidence:
```json
{"value": "2024-12-02", "evidence": [{"chunk_id": 7, "quote": "০২/১২/২০২৪"}]}
```
The quote must be an exact substring of that chunk's text; a field whose quote fails this
check is reset to `null` (ARCHITECTURE §4). In OpenAPI these appear as `StrField`,
`IntField`, `FloatField`, `DateField`, `StrListField`, `DegreeField` and `ApplyModeField`.

Fixed value sets:

| Name | Values |
|---|---|
| degree level | `Class 8`, `JSC`, `SSC`, `HSC`, `Diploma`, `Bachelor`, `Masters`, `PhD` |
| role | `seeker`, `admin` |
| source type | `digital`, `scanned`, `bijoy` |
| apply mode | `online`, `post_or_in_person`, `email_or_in_person` |
| verdict | `eligible`, `not_eligible`, `unclear` |
| check name | `age`, `degree`, `result`, `experience`, `subject` |
| check status | `pass`, `fail`, `unknown` |
| route | `fact_lookup`, `eligibility`, `summary`, `out_of_scope` |

## 4. Errors

Every error, including validation errors and unknown routes, has this body:
```json
{"error": {"code": "consent_required", "message": "Give consent before uploading a CV.", "retry_after": null}}
```

| Code | Status | When |
|---|---|---|
| `validation_error` | 422 | body, query or path failed validation |
| `unauthorized` | 401 | missing, invalid or expired token |
| `invalid_credentials` | 401 | wrong email or password at login |
| `forbidden` | 403 | wrong role |
| `consent_required` | 403 | CV or profile call before `POST /me/consent` |
| `not_found` | 404 | no such resource, or it belongs to another user |
| `email_taken` | 409 | register with an existing email |
| `profile_required` | 409 | eligibility requested without a confirmed profile |
| `file_too_large` | 413 | over 5 MB (CV) or 10 MB (circular) |
| `unsupported_file` | 415 | wrong type, or content does not match the type |
| `too_many_pages` | 422 | circular over 20 pages |
| `unreadable_file` | 422 | no text could be extracted |
| `rate_limited` | 429 | per-IP limit, or the LLM free tier is busy; `retry_after` is set |
| `not_implemented` | 501 | the route is still a stub |
| `internal_error` | 500 | anything else |

## 5. The ask stream

`POST /circulars/{circular_id}/ask` answers with `text/event-stream`. Each event has a name
and one JSON object as data. Design: docs/AGENT.md.

| Event | Data | When |
|---|---|---|
| `status` | `state` (`routing`, `searching`, `verifying`, `revising`, `busy`), `retry_after` | at each step; `busy` when the LLM free tier is rate-limited |
| `token` | `text` | pieces of the draft while it streams |
| `citation` | `ids[]` | sources the current answer cites |
| `critique` | `round`, `passed`, `sentences[]` (`text`, `verdict`, `reason`) | after each critique |
| `final` | `answer`, `outcome`, `language`, `route`, `citations[]`, `n_llm_calls`, `cached` | always last |

Source ids: `c:<chunk_id>` is a passage (fetch it with `GET /chunks/{chunk_id}`), `p` is the
user's profile, `e:<post_id>` is that post's eligibility result.

Rules for the client:
- Streamed `token` text is unverified. Show it as "verifying…". The text in `final` is the
  answer and replaces whatever was streamed.
- `outcome` is `answered`, `abstained` (not clearly stated in the circular) or `refused`
  (off-topic).
- After `status` with `busy`, the stream ends with a `final` event only if the retry
  succeeded; otherwise the request ends with error `rate_limited`.

Example:
```
event: status
data: {"state": "searching", "retry_after": null}

event: token
data: {"text": "আবেদনপত্র জমাদানের শেষ তারিখ "}

event: final
data: {"answer": "আবেদনপত্র জমাদানের শেষ তারিখ ০২/১২/২০২৪ [c:7]।", "outcome": "answered", "language": "bn", "route": "fact_lookup", "citations": ["c:7"], "n_llm_calls": 3, "cached": false}
```

## 6. Changes from the ARCHITECTURE draft

| Change | Reason |
|---|---|
| `PostReq.age_limit` added | age limit differed per post in test circular c01 |
| `PostReq.grade` added | FR-10 lists grade; models confused grade with degree, so it gets its own field |
| `FactCard.apply_mode` added | separates "apply online" from "send by post" without parsing free text |
| Degree levels `Class 8` and `JSC` added | 7 of 15 test circulars have posts at these levels |
| `GET /me` added | the UI needs role, consent and profile state after login |
| `POST /me/consent` added | consent has to exist before the CV upload, not at profile save (FR-02) |
| `status` event added to the ask stream | "busy, retry in N seconds" on the free tier (ADR-009) |
| `citation` ids are strings (`c:7`, `p`, `e:3`) | answers also cite the profile and eligibility results |
| one error body for every status | the frontend handles errors in one place |
| `ProfileOut.version` added | part of the answer cache key (ARCHITECTURE §6) |

## 7. Changing the contract

1. Edit `backend/app/core/schemas.py` or the routes.
2. `cd backend && UPDATE_OPENAPI=1 .venv/bin/pytest tests/test_contract.py`
3. `cd frontend && npm run types`
4. Update this page and note the change and its reason in `IMPLEMENTATION.md`.

`test_contract.py` also checks that the endpoint list is exact, that every private route
rejects a request with no token, that errors share one shape, and that the `FactCard`
schema can hold all 15 labelled circulars.
